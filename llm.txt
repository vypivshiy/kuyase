# KUYASE (К.У.Я.С.Э.) — Кустарный Универсальный Яндекс Станции Эмулятор

> Hardware-in-the-loop QEMU (`qemu-system-aarch64`) emulator for Yandex Station smart speakers running Linux Buildroot firmware (Amlogic SoCs). Provides kernel/userspace peripheral emulation (`SN3236` I2C LEDs, `vfb` framebuffers, `sysfs` LEDs/clocks, `uinput` buttons/ToF, `IIO`/`thermal` sensors, `snd-aloop` ALSA audio), local Quasar Protobuf IPC stubs (`aliced` `:9875`, `yio_audio` `:9850`, `iohub_services` `:9903`), ADB root access (`:15555`), and the `Virtual Speaker Twin` web visualizer + REST API (`:18091`).

## Repository Layout

- `hw-bridge/`: Rust source for the guest `qemu-hw-bridge` daemon (compiled statically for `armv7-unknown-linux-musleabihf` via `rust-lld` so one binary runs on both 32-bit `armhf` and 64-bit `aarch64` guests).
  - `hw-bridge/src/main.rs`: Entrypoint, `/dev/uinput` creation, thread startup.
  - `hw-bridge/src/state.rs`: `BoardProfile` auto-detection and shared `BridgeState`.
  - `hw-bridge/src/devices.rs`: Trait-based peripheral abstraction (`LedRingDevice`, `AuxLightDevice`, `FrontDisplayDevice`, `AudioSubsystemDevice`, `BoardPeripherals`), including `Sn3236I2cRing`, `SysfsFbLedRing`, `OrionAmbilightDevice` (`12×2` RGBW `/dev/fb0`), `OrionMatrix21x12Display` (`21×12` monochrome LED screen `/dev/fb1`), and `OrionQuadAcm8625Audio` (`4× ACM8625S` + `96 kHz / 38.4 kHz` Ultrasound TDM).
  - `hw-bridge/src/leds.rs`: `.led` animation parser/player (`ring` & `ambilight`) and volume arc generator.
  - `hw-bridge/src/tts.rs`: Pure procedural Russian Formant TTS synthesizer (Rosenberg glottal source + 4-formant Klatt cascade/parallel resonator bank, Russian orthoepy, proclitic merging, and 3-point `IK-1/2/3` pitch contours).
  - `hw-bridge/src/audio.rs`: ALSA `snd-aloop` (`hw:0,1`) capture, chunked TTS playback with `STOP_TTS` interruption, WAV ring buffer, 440 Hz test tone, `libasound_module_ctl_Saved.so` stub generator.
  - `hw-bridge/src/input.rs`: Linux `uinput` device creation and `EV_KEY` / `EV_ABS` event injection.
  - `hw-bridge/src/ipc.rs`: TCP servers for Quasar IPC (`:9875` `aliced`, `:9850` `yio_audio`, `:9903` `iohub_services`) and voice injection dialog state machine.
  - `hw-bridge/src/proto.rs`: Zero-dependency Protobuf wire encoder/decoder for `QuasarMessage` (`[u32_le_len][payload]`).
  - `hw-bridge/src/http.rs`: HTTP REST server (`:8091` in guest -> `:18091` on host) and `/sys` sensor writers.
  - `hw-bridge/src/dashboard.html`: Single-page web UI (`Virtual Speaker Twin`) with live WebAudio speaker streaming (`[LIVE SPEAKER: ON]`), HTML5 WAV buffer player, 36-LED ring + 12×2 RGBW ambilight SVG, 7-segment clock / 21×12 monochrome matrix SVG, and 4× `ACM8625S` + Ultrasound TDM telemetry.
- `guest-init/equasar-qemu-init.sh`: Guest `PID 1` (`/quasar-qemu-init.sh`) that mounts virtual filesystems, spoofs `/proc/device-tree`, synthesizes `/sys/class/leds/*`, `/sys/class/graphics/fb0..2`, `/sys/bus/i2c/devices/*`, `/sys/class/power_supply/ya_pd`, and ALSA devices (`pcm.speakers`, `pcm.ultrasound`, `pcm.bluetooth`), starts `/usr/bin/adbd` (`:5555`), and launches `/usr/local/bin/qemu-hw-bridge`.
- `kernel/build-kernel.sh`: Builds Linux `6.6.60` `arm64` (`kernel/Image`) with `CONFIG_COMPAT=y`, `snd-aloop`, `uinput`, patched `drivers/i2c/i2c-stub.c`, and 3-framebuffer `drivers/video/fbdev/vfb.c` (`fb0`, `fb1`, `fb2`).
- `scripts/prepare-rootfs.sh`: Unpacks a Firmware Dump (`rootfs.tar.gz`, `ubi0_0_rootfs.img`, `mtd3_system.bin`, `system.img[.gz]`) into `work/<board>-system-orig.ext4` and injects `quasar-qemu-init.sh`, `adbd`, and `qemu-hw-bridge` into `work/<board>-system.ext4`.
- `scripts/run-qemu.sh` / `scripts/run-qemu.ps1`: Launches `qemu-system-aarch64` with port forwarding (`:18091 -> :8091`, `:18090 -> :8090`, `:15555 -> :5555`).
- `scripts/dump-from-adb.sh` / `scripts/dump-from-adb.ps1`: Pulls a clean Firmware Dump from a physical speaker over ADB (`:5555`).
- `tests/test_qemu_multi_board.py`: End-to-end integration test suite verifying ADB, LEDs, clock, buttons, sensors, voice injection, IPC hijack/vocalize, and ALSA capture across all built images in `work/`.

## Supported Board Profiles (`board_slug`)

### Tested Profiles
- `yandexmini` (Станция Мини, `YNDX-0004`, 32-bit `armhf`): 6-LED ring via I2C `SN3236` (`0x3c` on `/dev/i2c-0`), `VL53L0X` ToF sensor, 4 mics.
- `yandexmini2` (Станция Мини 2, `YNDX-00021`, 32-bit `armhf`): 6-LED ring (`mini2:*:ring0..5`), 7-segment clock (`mini2:white:clock*`), `LTR-308` ALS, 4 mics.
- `yandexmicro` (Станция Лайт, `YNDX-00025`, 32-bit `armhf`): 3-LED ring (`micro:*:ring0..2`), 4 mics.
- `cucumber` (Станция Миди, `YNDX-00054`, 64-bit `aarch64`): 24-LED ring (`/dev/fb0` or `cucumber:*:ring0..23`), 6-LED logo (`/dev/fb1` or `cucumber:*:logo0..5`), 7-segment clock (`cucumber:white:clock-*`), `LTR-308` ALS, 4 mics.
- `orion` (Станция 3, `YNDX-00055`, 64-bit `aarch64`): 36-LED ring (`/dev/fb2` `name="ring"` or `orion:*:ring0..35` + `orion:ring{A,B,C}:sync`), 12×2 RGBW ambilight (`/dev/fb0` `name="ambilight"`, `12×1` `48 bpp` + 96 sysfs channels `orion:{red,green,blue,white}:ambilight{0..11}{a,b}` + `orion:ambilight{A,B,C}:sync`), `21x12` monochrome LED matrix display (`/dev/fb1` `name="YNDX LED screen"`, `252` pixels, `756` bytes `24 bpp`, `gowin_led_device.ko`), 4× `ACM8625S` Class-D amplifiers (`3-002d` `woofer`, `3-002e` `lr`, `3-002c` `center`, `2-002c` `us`), separate Ultrasound TDM-A (`hw:0,0` / `pcm.ultrasound`, `96 kHz` sample rate, `38.4 kHz` carrier), `light-sensor-top` (`LTR-308`) ALS, USB-C PD (`husb238_pd` `20V`), 6 mics.

### Auto-Profiled (Untested)
- `plum` (Станция Лайт 2, `armhf`), `bergamot` (Станция Мини 3, `armhf`), `pickle` (Станция Мини 3 Про, `aarch64`), `station2` (Станция 2 / `yandex,station-midi`, `armhf`), `mango` (Станция Стрит, `armhf`), `saturn` (Умный хаб Яндекса, `armhf`).

### Unsupported Devices
- Android / YaOS devices (`tulip-d1` Станция 1, `yandexstation_2` Станция Макс / Макс с Zigbee, Станция Дуо Макс, ТВ Станции) are not supported.

## Guest Hardware & IPC Interfaces (Inside QEMU)

### 1. Trait-Based Peripherals (`hw-bridge/src/devices.rs`)
All board-specific hardware peripherals are encapsulated behind 4 `Send + Sync` traits in `BoardPeripherals`:
- **`LedRingDevice`**:
  - `Sn3236I2cRing` (`yandexmini`, bus `/dev/i2c-0`, address `0x3c`):
    - `0x00`: Shutdown register (`bit 0`: `1` = normal operation, `0` = software shutdown).
    - `0x01..0x12`: 18 PWM brightness registers for 6 LEDs in **BGR** order (`LED i`: `B = 0x01 + i*3`, `G = 0x02 + i*3`, `R = 0x03 + i*3`).
    - `0x25`: PWM & Control Update register. Writing any byte latches shadow values from `0x01..0x12` and `0x26..0x37` to the active LEDs.
    - `0x26..0x37`: 18 LED Control registers (`bit 0` = `OUT_EN`, `bits 2:1` = `SL` current divider: `00` = `Imax`, `01` = `Imax/2`, `10` = `Imax/3`, `11` = `Imax/4`).
    - `0x4a`: Reset register. Writing any byte clears all registers (`0x00..0x4b`) and turns off all LEDs.
  - `SysfsFbLedRing` (`orion`, `cucumber`, `yandexmini2`, `yandexmicro`, etc.):
    - Resolves ring framebuffer by `/sys/class/graphics/fb*/name == "ring"` (`/dev/fb2` on `orion`, `/dev/fb0` on others).
    - Direct writes to `/sys/class/leds/<prefix>:<color>:ring<N>/brightness` (`0..255`) require setting `trigger` to `none` first (`echo none > trigger`). Writing `brightness` while `[ledfb-ring]` is active increments `led_trigger_conflict_count` and is rejected.
- **`AuxLightDevice`**:
  - `OrionAmbilightDevice` (`orion`): 12 dual-channel RGBW zones via `/dev/fb0` (`name = "ambilight"`, `12×1`, `48 bpp`, 72 bytes) and `/sys/class/leds/orion:{red,green,blue,white}:ambilight{0..11}{a,b}` + `/system/vendor/quasar/ledpatterns/ambilight/*.led`.
  - `LogoSysfsFbDevice` (`cucumber`, `pickle`, `mango`): `logo0..N` in `/sys/class/leds/<prefix>:*:logo*`.
- **`FrontDisplayDevice`**:
  - `SegmentClockSysfsDisplay` (`yandexmini2`, `cucumber`, `bergamot`, `pickle`, `plum`): 7-segment clock `/sys/class/leds/<prefix>:white:clock*` (`a1..g4`, `p3`, `q3`, `h1`, `m1`, `deg`).
  - `OrionMatrix21x12Display` (`orion`): Monochrome LED dot-matrix `21×12` (`252` pixels) on `/dev/fb1` (`name = "YNDX LED screen"`, `756` bytes `24 bpp`, `gowin_led_device.ko`). Renders `4×7` glyphs (`OrionFrontPanelLedFrameBuilder`), volume overlay, and matrix `.led` animations (`pattern:joy`, `pattern:volume`, `pattern:mute`) from `/system/vendor/quasar/ledpatterns/screen/`.
- **`AudioSubsystemDevice`**:
  - `OrionQuadAcm8625Audio` (`orion`): Emulates 4× `ACM8625S` I2C Class-D amplifiers (`3-002d` `woofer` -> `orion-acm8625-woofer.cfg`, `3-002e` `lr` -> `orion-acm8625-lr.cfg`, `3-002c` `center` -> `orion-acm8625-center.cfg`, `2-002c` `us` -> `orion-acm8625-us.cfg`) with `hardvold` gain curve (`-66.6 .. 0.0 dB`, ramp `-6 dB`) and separate TDM-A Ultrasound (`hw:0,0` / `pcm.ultrasound`, `96000 Hz`, `38400 Hz` carrier, `600 Hz` bandwidth, 4 channels).

### 2. Input Devices (`/dev/input/event0..2`)
- `event0`: `"STM VL53L0 proximity sensor"` (`EV_ABS`: `ABS_DISTANCE = 0x19`, `0x12` in mm).
- `event1`: `"AML-AUGESOUND Headphones"` (`EV_SW`).
- `event2`: `"adc_keypad"` (`EV_KEY`: `KEY_MUTE = 113`, `KEY_VOLUMEDOWN = 114`, `KEY_VOLUMEUP = 115`, `KEY_VOICECOMMAND = 582`).

### 3. Sensors (`sysfs` / `IIO`)
- SoC Temperature: `/sys/class/thermal/thermal_zone0/temp` (millidegrees Celsius, e.g. `42500` = `42.5 °C`).
- Ambient Light (`ALS`): `/sys/bus/iio/devices/iio:device0/in_illuminance_raw` (lux).
- ADC Voltage: `/sys/bus/iio/devices/iio:device0/in_voltage6_mean_raw`.

### 4. Audio (`ALSA` & Formant TTS)
- Loopback card `Loopback` (`snd-aloop`): playback to `default` (`hw:0,0,0` + `softvol` control `Master` `0..10000`) is captured by `qemu-hw-bridge` from `hw:0,1,0` (`48000 Hz`, `S16_LE`, stereo, with 400 ms inter-word pause hangover) and exposed at `GET /api/audio/output.wav` (supports `?from=<byte_offset>` for live WebAudio delta streaming).
- Ultrasound TDM (`pcm.ultrasound` on `hw:0,0,2`, `96000 Hz`, stereo/4ch, `softvol` control `Ultrasound Playback Volume`).
- Expressive Russian Formant TTS (`hw-bridge/src/tts.rs`): procedural synthesis (number expansion, proclitic merging, Russian orthoepy/palatalization, Bryzgunova `IK-1/2/3` 3-point pitch contours, Rosenberg glottal pulse + 4-formant Klatt cascade/parallel resonator bank) streamed to ALSA in `40 ms` chunks with immediate `STOP_TTS` / `CANCEL_DIALOG` interruption.

### 5. Local Quasar IPC Sockets & Logs
All sockets use little-endian length-prefixed framing `[u32_le_len][QuasarMessage protobuf]`:
- `127.0.0.1:9875` (`aliced`): Accepts `QuasarMessage.remoting (field 210)` -> `Remoting { remote_object_id = 7 ("AliceCapability"), alice_capability_method = 8 }`:
  - `method = 6` (`CANCEL_DIALOG_AND_CLEAR_QUEUE`) or `method = 14` (`STOP_TTS`): Cancels active dialog within the `1680 ms` Hijack Window (`aliced_hijack_count++`).
  - `method = 18` (`START_VOCALIZE`) with `vocalize_directive (field 13) -> Text (field 1)`: Synthesizes speech in ALSA (`aliced_say_count++`, sets `last_spoken_text`).
- `127.0.0.1:9850` (`yio_audio`): Streams `QuasarMessage.mic_input_data (field 158)` (`IOAudioChannelData`: `raw_mic_0..3`, `vqe_0`, `doa_angle` in fields `5`/`6`) at 20 Hz to subscribed clients.
- `127.0.0.1:9903` (`iohub_services`): Broadcasts `io_event` key/button notifications.
- `/tmp/daemons_logs/maind.log` (symlinked to `/data/quasar/daemons_logs/maind.log` and `/bkupgrade/data/quasar/daemons_logs/maind.log`): Receives `[sdk] onRequestStateChanged: LISTENING, recognizedPhrase='...'` lines upon voice injection.

## Host Ports & Control Endpoints

- `127.0.0.1:15555` -> Guest `:5555` (ADB root shell: `adb connect 127.0.0.1:15555`).
- `127.0.0.1:18090` -> Guest `:8090` (Forwarded port for custom guest services/SDKs).
- `127.0.0.1:18091` -> Guest `:8091` (`Virtual Speaker Twin` UI & REST API):
  - `GET /api/state` — Full JSON state (`ring_pixels`, `logo_pixels`, `aux_light_kind`, `display_kind`, `screen_width`, `screen_height`, `screen_pixels`, `clock_segments`, `amplifiers`, `ultrasound`, `alice_state`, `aliced_hijack_count`, `aliced_say_count`, `ipc_error_count`, `led_trigger_conflict_count`, sensor values, logs).
  - `GET /api/audio/output.wav[?from=<byte_offset>]` — Captured ALSA playback audio (`WAV`, 48 kHz stereo; optional `from` byte offset returns only new PCM frames for live WebAudio streaming).
  - `POST /api/hw/button` — `{"button": "action"|"mute"|"volume_up"|"volume_down", "action": "single"|"double"|"triple"|"long"}`
  - `POST /api/hw/volume` — `{"volume_level": 0..10}`
  - `POST /api/hw/led` — `{"pattern": "alice_listening.led"|""}`
  - `POST /api/hw/clock` — `{"text": "19:30°"|"pattern:joy", "brightness": 255}` (writes to 7-segment `sysfs` clock or `orion` `21×12` LED matrix `/dev/fb1`).
  - `POST /api/hw/sensor` — `{"temp_c": 42.5, "als_lux": 320, "tof_mm": 165, "doa_angle": 90, "swipe": true}`
  - `POST /api/voice/inject` — `{"phrase": "...", "doa_angle": 90, "wake_only": false}`
  - `POST /api/ipc/test` — `{"cmd": "cancel_dialog"|"stop_tts"|"vocalize", "text": "..."}`
  - `POST /api/audio/test_tone` — `{}`
  - `POST /api/audio/clear` — `{}`
  - `POST /api/hw/poweroff` — `{}`
