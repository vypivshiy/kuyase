# Папка для пользовательских дампов прошивок (`backups/`)

>[!warning]
> **Дампы прошивок не входят в репозиторий `KUYASE`** (по соображениям авторского права и размера образов).
> Кроме того, автоматические фильтры очистки (`sanitize`) работают по известным шаблонам и несовершенны — перед публикацией или передачей своего дампа / образа `.ext4` обязательно проверьте его вручную на отсутствие личных ключей, токенов и конфигов.

Чтобы собрать и запустить виртуальную колонку, получите дамп одним из двух способов:

1. **Снимите дамп со своей колонки по сетевому ADB (`<IP>:5555`)**:
   ```bash
   # Встроенным клиентом kuyase (без установки adb):
   kuyase dump 10.1.1.56

   # Либо автономным скриптом (без установки эмулятора, нужен только adb):
   ./scripts/dump-from-adb.sh 10.1.1.56
   ```
   В графическом интерфейсе `kuyase` это делается через кнопку **«Образы и QEMU...» -> «Снять дамп и собрать .ext4»**. Чистый системный архив `rootfs.tar.gz` (без раздела `/data` и без токенов/паролей Wi-Fi) сохраняется в папку `backups/dump-<board>-<timestamp>/`. Подробности и ручные команды — в [`../DUMP_GUIDE.md`](../DUMP_GUIDE.md).

2. **Положите готовый дамп в папку `backups/`**:
   Поддерживаются распространённые форматы дампов системного раздела:
   * Архив корневой ФС: **`rootfs.tar.gz`** / **`*.tgz`** / **`*.tar`** / **`*.zip`**;
   * Образ тома UBIFS или раздела NAND UBI: **`ubi0_0_rootfs.img`**, **`mtd3_system.bin`**;
   * Образ раздела eMMC (`ext4`): **`system.img`** или **`system.img.gz`**.

После помещения дампа в `backups/` соберите загрузочный образ `work/<board>-system.ext4` в userspace (без WSL2 и `sudo mount -o loop`) и запустите эмулятор:
```bash
cargo run --release -p kuyase -- prepare
cargo run --release -p kuyase
```
